# Image policies (Debian image)

Status: proof of concept, `images/debian/mkosi`; verified in QEMU/OVMF on Debian 13 (systemd 257.13), 15.11.2026.

| Topic | Policy | Why / verified |
|---|---|---|
| Unit enablement | `/usr/lib/systemd/system-preset/00-foil.preset`: `disable *`. A unit runs only if it is wired with a `.wants`/`.requires` symlink under `/usr/lib/systemd/system` (verity-protected) | `/etc` is empty, so a boot is a "first boot" whenever `/etc/machine-id` is not set before PID1 starts (before the machine-id unit was enabled, every boot; now only a node without a usable SMBIOS UUID), and on a first boot Debian's presets enable every unit with an `[Install]` section (this is how `systemd-pcrlock-*` and test units ran). `disable *` holds on every boot, first or not. Verified: `systemctl list-unit-files --state=enabled` is empty; running services: dbus, journald, logind, networkd, timesyncd, udevd, serial-getty |
| Boot failure | `emergency.service` and `rescue.service` reboot (`reboot-force`) instead of a shell, in the initrd (`images/debian/foilbird-initrd`) and in the system | without it a slot that fails in the initrd hangs forever and its boot try is never spent. Verified: broken verity metadata of a new slot → three reboots → previous release (each try ≈100 s, mostly the 90 s device timeout) |
| machine-id | `foil-machine-id.service` in the initrd runs `/usr/libexec/foil-machine-id` (C, no shell), which writes `/sysroot/etc/machine-id` from the SMBIOS system UUID; no UUID, all-zero or all-F → random id for that boot, with a console warning | systemd itself uses the DMI UUID only under KVM. At first the unit was never enabled (`.gitignore` `initrd*` hid its `initrd-root-fs.target.wants/` link), unnoticed because QEMU/KVM gives the same id anyway; the boot log now shows `foil-machine-id: <id> (from SMBIOS)`. v0 limitation: a node without a usable SMBIOS UUID is not supported: its machine-id, and with it the DHCP DUID and the journal directory, changes on every boot; fix in v1 |
| Time | `systemd-timesyncd`, wired into `sysinit.target`. No servers in the image: `/usr/lib/systemd/timesyncd.conf.d/10-foil.conf` empties `NTP=` and `FallbackNTP=` (Debian's compiled-in pool is off). Servers come from `NodeConfig.time.servers` (the agent renders `/run/systemd/timesyncd.conf.d/50-foil.conf`) and from DHCP; timesyncd asks the `NTP=` (agent) servers first and the DHCP ones only after those time out (verified, systemd 257). `systemd-time-wait-sync` is not enabled, so `time-sync.target` does not wait | mTLS, Kubernetes. The first join waits for the synchronized kernel clock itself; afterwards a lost NTP is only reported by the agent (Warn), it is not a boot gate |
| OS identity | `/usr/lib/os-release`: `ID=foilbird`, `ID_LIKE=debian`, `NAME`/`PRETTY_NAME` "Foilbird OS", Debian's `VERSION_ID`/`VERSION`/`VERSION_CODENAME` kept, Debian's URLs dropped (`mkosi.finalize`; initrd and recovery: `tools/no-interpreters.finalize`; the build fails unless `VERSION_ID` is the major of `/etc/debian_version`) | the product's name on the node (kubelet `OS-IMAGE`, the boot menu, `GetInfo` `os_id`); the base release stays visible to scanners through `ID_LIKE` and `/etc/debian_version` (T13) |
| OS identity in /etc | `/etc/os-release` and `/etc/debian_version` are regular files: tmpfiles `C` copies of `/usr/lib/os-release` and `/usr/share/factory/etc/debian_version` (`mkosi.finalize` drops systemd's own `L /etc/os-release` line, the build fails unless exactly one line per file remains) | vulnerability scanners read the OS from these files; Trivy does not follow the links and then reports no OS and no packages (T13). Copies are made on every boot (`/etc` is tmpfs), so they always match the booted `/usr` |
| dpkg database | `/var/lib/dpkg` is a read-only bind mount of `/usr/lib/foilbird/dpkg` (`var-lib-dpkg.mount`), holding only `status` with the stanzas of removed packages dropped; no tmpfiles line may touch `/var/lib/dpkg` (the build fails otherwise) | scanners read the packages from a regular file there; Trivy does not follow a link and then reports 0 packages. A bind, not a copy: `/var` is persistent, a copy would go stale after an update; the bind always shows the booted `/usr` and also hides the link earlier releases left there. The stash is not under a `…/var/lib/dpkg/status` path, else Grype counts it as a second database and reports every finding twice |
| Journal | `tmpfiles.d/foil-journal.conf` creates `/var/log/journal` | persistent journal for the previous boot (Debian creates it in a postinst, outside `/usr`) |
| No interpreters in units | units, drop-ins and generators of the base image call binaries directly (`test`, `systemd-*`, `nvidia-modprobe`, …) or a helper in `/usr/libexec` that is not a shell script; never `/bin/sh -c`. Build-time scripts (`mkosi.*`) are not affected. The initrd and the recovery UKI have no shell and no interpreter at all (row Initrd) | a profile (for example `k8s-worker`) may ship no shell at all; a shell call there fails with 203/EXEC (seen: the install check failed after the slot was written) |
| No extensions (sysext/confext) | `systemd-sysext`/`systemd-confext` (services, `systemd-sysext.socket`, `systemd-sysext@.service`, binaries) are removed from the image and from the recovery UKI (`RemoveFiles=`); and from the initrd (`images/debian/foilbird-initrd`). Cmdline: `systemd.allow_userspace_verity=0` | `/usr` and `/etc` are exactly what the signed image ships: an extension image on `/var`, in `/run` or on the ESP (stub `.extra.d/`, `/.extra/sysext`) is never merged, and dm-verity signatures are checked only by the kernel keyring, not against certificates in `/etc/verity.d` or `/run/verity.d` (as on Talos, which has no extensions at runtime) |
| Initrd | the slot UKIs boot `images/debian/foilbird-initrd` (`Initrds=` in `mkosi.conf.d/40-initrd.conf`, built by its `build.sh` before the image), not mkosi's default initrd: Debian packages of the same release only (systemd, udev, kmod, dmsetup, systemd-cryptsetup, the TPM2 libraries and their dependencies), Debian's `os-release` as `initrd-release`, no shell, no interpreter (bash, dash, perl, mawk, sed) and no `#!` script; the build fails if one is left or `os-release` is not Debian's (`images/debian/tools/no-interpreters.finalize`, also for the recovery UKI). The dpkg status of the initrd is kept at `/usr/lib/foilbird/dpkg/status` for scanners. The kernel modules come as a separate archive from the image's own kernel | mkosi's default initrd is Debian too, but its content follows mkosi's built-in list (bash, dash, perl, mawk, less, 179 scripts) and has no package database, so scanners see nothing in it; as on Talos, nothing in the boot path needs a shell. `/etc/initrd-release` is an absolute link: read on an unpacked tree it shows the reading machine's `os-release` |
| PoC checks | none in a product image: `foil-poc-check` comes only with the extra tree `images/debian/poc-checks/tree`, its T9 test modules (one signed with a foreign key) and `cuda-init` in `/usr/lib/foil-poc-check` only with `FOILBIRD_POC_CHECKS=1`; `images/debian/tools/lab-gate` fails a build that carries any of them | `foil-poc-check` is a bash script and powers the machine off; a module signed with a foreign key has no place on a node |
| NVIDIA | only in an image with the NVIDIA userspace (`--variant gpu`): the open kernel modules (DKMS in the build stage, signed with the db key), their SBOM records, and nvidia-persistenced wired by `mkosi.finalize`. An image without it (`--variant cp`) has no NVIDIA component; `mkosi.build` and `mkosi.finalize` fail the build if one is there. Kept in every image: `foil-blacklist.conf` (nouveau, nvidiafb off), so no other driver binds an NVIDIA card | `--variant cp` build manifest: no `nvidia*.ko` from DKMS, no `nvidia-persistenced` drop-in, user or link |
| Update keyring | see `docs/updates.md` (exactly the release key, checked at build time) | |

Known limitation: some boards ship the same SMBIOS UUID on a whole batch. The machine-id is then not unique; uniqueness
is checked at registration (controller), a duplicate is refused with a warning.

`systemd-pcrlock-*` no longer run (preset policy), and the image does not need them: `/var` is bound to PCR 7 and a
signed PCR 11 policy (`foil-repart.service`), nothing uses a pcrlock policy. Why `systemd-pcrlock-make-policy` failed
from the second boot on (systemd 257, reproduced in QEMU): on the first boot it allocates an NV index, seals its PIN to
a policy that includes PCR 12 (empty then) and writes `pcrlock.json` to `/var` and a copy as a boot credential
`/boot/loader/credentials/pcrlock.<entry-token>.cred`. systemd-stub measures that credential into PCR 12 on the next
boot ("Global credentials initrd"), so PCR 12 no longer matches the stored policy, the PIN cannot be unsealed
(`Esys_PolicyAuthorizeNV`, TPM_RC_VALUE, "State not recoverable") and every later run fails. The NV index stays in the
TPM. If pcrlock is ever wanted, PCR 12 and the ESP credential have to be accounted for first.
